# icli 1.0.0+korboy2

Complete feature notes for this fork, based on upstream icli 1.0.0. This release
includes the earlier fork additions, audio output selection, byte-offset file
reads and background work alongside interaction leases. It runs on-device and
returns JSON for automation; `--human`, `--compact` and per-command `--help`
provide readable output and exact options.

## Interaction leases and automation

- File operations, logs, package inspection, process/device information and other audited background commands run while another task holds a lease, without its token. Background commands never acquire, release or renew that lease, including when the caller supplies the holder's token.
- Input, navigation, app lifecycle changes, shared settings changes and other guarded operations still require the holder's token while a lease exists. Unclassified commands are guarded by default. Device-lock checks, permissions and `--force` requirements remain independent.
- `batch` runs JSON command lists with expectations, delays and failure handling; `session` keeps one process open and executes JSON lines. Both enforce each step's own lease policy. A background step can run while a following guarded step is refused.
- `status` reports the lock/screen state, frontmost app, keyboard, overlay, owner-only prompt, SpringBoard PID and boot time. `lease acquire|release|status` manages ownership and idle expiry. Guarded holder commands renew the lease; background-only observers can explicitly renew it using `lease acquire` with their existing token.
- The packaged SpringBoard indicator shows `icli: <owner>` above the home indicator, passes touches through, follows rotation/layout, and disappears on release or expiry. It is omitted from icli screenshots, OCR and UI trees; `lease indicator on|off` controls its visibility. First installation requires a respring to load the tweak.
- `ICLI_FAILURE_ARTIFACTS` saves error details, a screenshot and the accessibility tree for guarded failures. Background failures and lease refusals do not trigger UI captures.

See [the complete command policy](../usage/leases.md).

## Control Center, audio and device settings

- `cc list|get|set|toggle` controls Airplane Mode, Wi-Fi, Bluetooth, cellular data, Personal Hotspot, AirDrop, Focus/Do Not Disturb, flashlight level, rotation lock, Low Power Mode and appearance. Mirroring is read-only. Commands read the resulting state back and report whether it changed.
- AirDrop supports `off`, `contacts` and timed `everyone`; Focus supports on/off and named modes; the flashlight accepts on/off or a level from 0 to 1. Changes persist after icli exits.
- `cc audio list` discovers outputs by native name and exact UID. `cc audio select <uid>` waits for native confirmation, reports disappearance/rejection/timeouts and preserves each output's saved volume. Already-selected outputs are reported without switching.
- Device commands read/set brightness, audio volume/category, orientation and rotation lock, light/dark appearance, accessibility text size/display settings, Low Power Mode and time zone/automatic time-zone behavior. They also expose Developer Mode status/enabling and hardware buttons, including Siri, wake, power and volume.
- Location commands read, set and clear simulated coordinates. Darwin notifications can be read or posted with optional state.

See [device settings and audio](../usage/device-settings.md) and [entitlements](../entitlements.md).

## Verified UI actions, touch, keyboard and capture

- `ui tree` covers foreground apps and system UI such as the Home Screen, Spotlight, alerts, Control Center and the app switcher. It supports `--scope auto|app|system|all`, AX/OCR/combined sources, hierarchical output, clickable filtering and compact rows with trait names. App and SpringBoard trees can be read together.
- `ui perform` checks the intended app/process, unique visible enabled identifier, orientation, geometry and hit testing before dispatching once, then observes an appearance/disappearance/value change. Results distinguish refusal, verified completion and an action whose result was unconfirmed. Actions are never automatically retried.
- `ui perform --method accessibility` directly activates a control that advertises support. It retains and rechecks the remote AX reference and never falls back to a coordinate tap.
- `ui tap` ranks matches and rejects ambiguity; identifier, role, text matching and explicit index selection are supported. `ui fill` replaces text by label or point; `ui alert` answers alerts while refusing owner-only prompts; `ui prompt`, `ui back`, `ui wait` and `ui wait-gone` cover prompt detection, navigation and waits.
- `--expect`, `--expect-gone` and timeouts observe the result of taps, fills, alert answers and back actions. Waits use new screen frames where available, with bounded polling where frame notifications are unavailable.
- Touch includes taps, double taps, long presses, swipes, pinches, multi-point drags, touch sequences and system gestures. `screen scroll-by`, `swipe --no-momentum` and `ui scroll-to` support controlled scrolling; multi-stroke scrolling crosses the touch slop consistently to reduce accumulated shortfall. iPad pointer click/scroll commands are also retained.
- Input supports Unicode paste, character typing, clearing/submission, hiding the keyboard, shortcuts, arrows, digits, forward delete, repeat counts and raw HID events. Clipboard commands read/write text and images.
- Capture supports JPEG/PNG screenshots, width reduction, native resolution, Base64 and raw stdout; HEVC/H.264 movie recording; change/stability waits; and combined screen description. OCR supports regions, language selection, confidence filtering, fast recognition and compact output. On iOS 17+, OCR can use CPU recognition without a Metal device.

See [interaction and capture](../usage/interaction.md).

## FLEX, FlexUltra, scripting and MCP

- `icli flex` exposes the supplied FlexUltra catalog: 105 operations and 102 MCP tools. The iOS packages contain the probe agent, FLEX, the FlexUltra engine and Swift metadata runtime. The agent attaches on demand without restarting the target and remains loaded until the app exits; an older attached agent may need one app relaunch after an update. There is no resident broker or network listening port.
- Target discovery, resolution, history, identity/generation checks and health reports identify the process being inspected. Live object handles are process-generation specific; objects can be pinned and unpinned.
- Runtime commands inspect classes, images, protocols, methods, properties and ivars. Heap commands find instances, allocations, subclasses, incoming references and reference graphs. Object commands inspect/read/change supported values and invoke supported methods.
- UI inspection includes views/controllers, key windows, supported activation, text/value changes, navigation, scrolling, alerts, screenshots and saved snapshot comparisons. The graphical FLEX explorer can be shown or hidden.
- Storage tools cover app files, defaults, accessible Keychain entries, SQLite and loaded Realm databases. Default/object/UI experiments support their documented rollback and commit operations. Bookmarks and global inspectors retain useful inspection entry points.
- Network recording can be enabled, disabled or queried explicitly. It records requests after FLEX loads while observation is enabled. App log history uses icli's recorder to avoid the iOS 17 FLEX log-decoding issue. Empty history is a valid result.
- Bounded method tracing uses ObjSee. Swift inspection exposes class metadata, field names and offsets; live Swift values and mirror construction remain disabled. Realm requires the target to load Realm and uses its own configuration/schema version; older files are refused rather than migrated.
- `icli flex mcp` serves newline-delimited JSON-RPC over stdin/stdout using the original `flexultra_*` names, schemas and annotations. MCP tool requests obey the lease policy and cannot be nested in a batch/session.
- `icli probe` provides JavaScriptCore evaluation and a REPL with an Objective-C reflection bridge, captured output and the documented `api()` methods. `probe --app` evaluates on an app's main thread; `--inspect` uses the object explorer, with optional getter evaluation and pagination. Geometry values include CGRect, CGPoint, CGSize, UIEdgeInsets and NSRange. Arbitrary CLI probe execution remains guarded because native calls can control the phone.

See [FlexUltra](../usage/flex.md) and [probe scripting](../usage/probe.md).

## App lifecycle, installation and permissions

- App commands list/search apps, filter user apps, inspect running/frontmost apps and their binary/data paths, and query URL handlers/schemes. Launch accepts bundle IDs or unique display names, arguments, environment variables, language and locale. Verified launch/relaunch reports process identity and launch time.
- URL/deep-link opening can check for a screen change. App Settings navigation verifies the resulting page. Privacy permissions can be read, granted, denied or reset; app reset clears the documented data and permissions while retaining Keychain/group containers. Network policy can be inspected or repaired.
- Native local DEB handling supports metadata, extraction, installation/removal, package state/list/comparison and repository-source management. It does not download dependencies or execute maintainer scripts/triggers; skipped scripts are reported.
- IPA installation supports bootstrap layouts and separate app/data containers. Container installs re-sign every Mach-O ad-hoc in-process, retain entitlements and add the Dopamine trust entitlement; the signature contains SHA-256 CodeDirectory, XML and DER entitlements. FairPlay-encrypted main binaries are refused; `--keep-signature` preserves the supplied signature.
- Container installs register as System by default, with optional User registration. Removal handles the supported icli/TrollStore app cases. Reading rejected installed executable signatures avoids the earlier invalid-page process kill.
- Registration/refresh handles plug-ins, application/system group containers, HOME/TMPDIR, data containers and Settings bundles, reads back the resulting registration, skips unchanged/foreign apps and reports incomplete registrations. The iOS 27 containerized registration path is retained where firmware permits it.

See [apps/files/logs](../usage/apps-files-logs.md) and [services/registration](../usage/services.md).

## Files, logs, lock/unlock and system tools

- Files support read/write, listing/search, copy/move/link/remove, directory creation, permissions/ownership, and plist reading/editing. `fs read --offset <bytes> --limit <bytes>` reads chunks; Base64 replies preserve exact bytes across UTF-8 boundaries. EOF/past-EOF reads are empty, negative offsets fail, and the full observed size and truncation status remain available.
- Logs support bounded unified-log capture with process/PID/subsystem/category/message/level filters applied before the line limit. Crash reports can be filtered by app, age/time, kind and count, read with byte caps, and summarized with report types. The newest app crash can be selected directly.
- `icli lock` checks locked/screen-off state and sends at most one power action. `icli unlock` uses an explicitly provisioned, device-only Keychain credential without stdin or a passcode prompt. Provision/forget/check operations, supplied-passcode keybag unlock and full `--dismiss` unlock are retained. Rejected-passcode history, failure budgets, backoff checks, buffer wiping and no-retry behavior apply; after reboot the saved item needs a first manual unlock. Workstation vault provisioning is documented separately and requires that external workstation tool.
- Launchd tools list/status/print/dump services and paths, bootstrap/bootout/load/unload, enable/disable, start/stop/kickstart/kill/remove, and read/change launchd environment. RootHide load/bootstrap rewrites paths as documented.
- System tools cover environment/basebin inspection, processes, jetsam/memory-pressure information, Keychain metadata and dedicated item operations, SSL-killswitch status, packet capture, account passwords from stdin, system app visibility, SpringBoard refresh/respring, boot-logo rendering and full/userspace reboot requests.
- Typed preference reads/writes/deletes use cfprefsd. `prefs --app` accesses the app's own container preferences; mutations can explicitly stop a running app where required.

## Swift libraries, platforms and delivery

- Swift Package products are `IcliKit`, `IcliSystem` and `IcliLaunch`. Libraries expose the in-process APIs; the CLI does not spawn subprocesses for device operations. ArchiveKit is statically linked and dependencies remain pinned through `Package.resolved`.
- Upstream 1.0.0's `InterfaceGeometry`/`withInterfaceGeometry` provides validated synchronous per-thread geometry scopes for metrics, AX and normalized input, with nested/throwing-scope restoration. Capture APIs refuse overrides because geometry alone does not select a display.
- iOS packages contain universal arm64/arm64e binaries and target iOS 15+. Rootless and experimental RootHide layouts are provided. The separate tvOS 15+ build has the documented touch/clipboard/device limitations. Package identity is `com.korboy.icli`, replacing/conflicting with `com.icli.icli` to prevent parallel installs.
- Full usage/API/development guides, the agent skill, entitlements, notices and dependency licenses accompany the complete archive. GitHub's source archives contain the full tagged source, including the vendored inspection runtimes. The standalone workstation `icli-unlock` helper is not part of the on-device DEB.

See [Swift integration](../swift-package.md), [installation](../install/install.md), [tvOS](../platforms/tvos.md) and [licenses](../../THIRD_PARTY_NOTICES.md).

## Validation boundaries

- The current signed iOS CLI was built for arm64/arm64e, installed on the rootless test phone and hash-matched. The focused lease regression passed 24 CLI invocations under another task's lease without its token: file/inspection access, guarded refusals, batch/session dispatch and omission of UI artifacts on background failures. The other holder was preserved.
- Host lease tests checked default guarding, background calls with/without tokens, unchanged lease data, owner renewal, expiry and independent screen-lock behavior. File-offset checks passed on Mac and phone, including exact byte slices, limits, EOF/past-EOF, negative offsets and incremental appends.
- Earlier focused audio testing verified Speaker ↔ AirPods selection, native completion events, output-specific saved volumes, no-op/missing-UID behavior and restoration; see [audio validation](../development/audio-output-validation.md). Earlier FlexUltra/UI/unlock runs are versioned in the development documentation.
- This release does not claim a new full acceptance run or broad hardware coverage. RootHide/tvOS package verification is separate from device acceptance; the current RootHide/tvOS binaries have not been qualified on those devices. See [testing](../development/testing.md).
