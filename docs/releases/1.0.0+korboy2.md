# 1.0.0+korboy2

- Interaction leases now allow audited background file work and inspection without the holder’s token. Guarded commands still fail with exit 75 for other runners.
- Background commands never renew leases. Batch and session enforce the policy per command; device-lock and force requirements remain independent.
- Arbitrary CLI probe execution is guarded because scripts can invoke native control APIs. Background failures do not collect UI failure artifacts.
- See [command policy](../usage/leases.md) and [testing](../development/testing.md#interaction-lease-policy).

Validation: universal arm64/arm64e rootless package built and installed on the test phone. Installed CLI SHA-256 `182c6297a9157aa4b4e8c764a57c7f1edbe5880ca165e6323c16cacfbac3f285` matched the build. The focused device regression passed 24 CLI invocations under another task’s existing lease, without its token: background files/inspection, guarded refusals, batch/session dispatch, and omission of UI artifacts on background failure. The existing holder was preserved. Host tests separately verified that background calls do not renew the lease, including with the holder token, and that owner renewal, expiry and screen-lock rules still work. The release workflow runs the host regression. Full acceptance, RootHide and tvOS device testing were not rerun.
