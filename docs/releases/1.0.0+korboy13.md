# 1.0.0+korboy13

- Add hidden app sessions through the optional Parallel package
  (`com.korboy.parallel` 1.1.0 or later): `icli parallel info`, `list`,
  `create [--launch] [--export]`, `launch`, `restart`, `stop`, `status`,
  `renew`, `rotate`, `gesture` and `release`. Each session owns one app, runs it
  in a scene that is never shown, and is authorized by its own token instead of
  the device lease, so several runners can drive different apps at once.
- `--parallel <session>` sends `screen tap`, `long-press`, `double-tap`,
  `swipe`, `pinch`, `shot`, `ocr`, `ui tree`, `ui tap` and `input type`,
  `paste` and `key` to the session's app. The token and app generation come
  from `--parallel-token`/`--parallel-generation` or `ICLI_PARALLEL_TOKEN`/
  `ICLI_PARALLEL_GENERATION`; a command for an earlier generation is refused
  with `stale_generation`. Options a session cannot honor are refused.
- The frontmost-app check ignores apps running in Parallel sessions, so `ui`
  commands and `app frontmost` keep working on the physical screen while
  sessions run (before, they failed with "frontmost application could not be
  verified").
- `icli tests` reports whether Parallel is loaded and speaks icli's protocol.
- The package suggests `com.korboy.parallel` on iOS. Without it, the new
  commands answer `parallel_unavailable` (exit 69).

Tested on an iPhone 15 Pro Max with iOS 17.1.1 (rootless): the new
`parallel_sessions` acceptance case (a hidden Calculator computed 7+8=15 through
`ui tap`, read back by `ui tree` and OCR, without the lease, while Settings stayed
the verified frontmost app; restart, stale generation, missing and wrong token)
and 17 existing screen, ui and input cases passed. `icli tests` passed 12 checks,
including Parallel's. Taps, typing, swipes, screenshots and OCR were also checked
in a Parallel fixture app, `ui tap` and OCR there in landscape too, and `ui tree`
in a hidden Chrome session.
